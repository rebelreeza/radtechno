Sync / ETL layer - one-way copy, read only from sources

ETL / Sync Tool

Reads from Shopify's API and Odoo's Postgres database on a schedule. Transforms data into consistent schemas. Loads into BigQuery. Never writes back to either source.

Tool options

Data warehouse - analytical layer, read-only, single source of truth

BigQuery - Central Data Warehouse

Every business event from every source accumulates here permanently. Optimized for analytical queries. Nothing is ever deleted. No live transactions. This is where every dashboard, report, and AI tool reads from.

Architecture rules

✓ Odoo is inventory source of truth ✓ Odoo pushes inventory → Shopify ✓ Shopify pushes orders → Odoo ✓ ETL pulls from both independently ✓ AI reads from BigQuery only ✓ BigQuery is append-only, historical ✗ BigQuery never pushes to Odoo or Shopify ✗ AI never writes to production systems ✗ Never run analytics against Odoo directly ✗ No Supabase needed - no custom apps yet

Why Odoo → Shopify for inventory

Shopify knows what's available to sell. Odoo knows what's actually in the warehouse. Odoo is authoritative. When a PO is received and confirmed in Odoo, it pushes the updated quantity to Shopify. Shopify doesn't calculate inventory - it displays what Odoo tells it.

Why pull from both in the ETL

Shopify has data Odoo never receives - abandoned carts, discount code attribution, storefront behavior, influencer referral UTMs. Odoo has data Shopify never sees - landed costs, PO history, accounting entries. Both are needed for the full picture.

Why BigQuery never feeds back up

BigQuery is a record of what happened - it's historical and analytical. It does not make things happen. If an AI agent needs to trigger a reorder in Odoo, it calls Odoo's API directly, not through BigQuery. The warehouse only ever receives data, never sends it.
