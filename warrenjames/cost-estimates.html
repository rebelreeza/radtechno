Cost Estimates - Infrastructure & AI

Projected monthly spend across existing tools, proposed data infrastructure, and AI use cases. Lean options first. Nothing sized beyond what the current stage actually warrants.

The core principle: start with the cheapest option that solves the problem. Spend is justified by scale, not ambition. At WJ's current size, AI token costs run $1–5/month - the real investment is architect time to get the decisions right, not compute. Every recommendation here has an upgrade path but doesn't require it.

Section 02

Data Warehouse Options

WJ's data volume at 70 stores is modest - a few million rows across orders, inventory, and financials. That's comfortably within the free tier of most warehouse products. The case for spending more only appears when query complexity, team size, or real-time requirements grow.

BigQuery Start here
$0–80/mo
Pay-per-query with no migration risk - grows with you from day one. First 10GB storage and 1TB queries/month are free. At WJ's scale, likely stays under $30/mo for months. Mature ecosystem, native Metabase and Anthropic/Claude integration via Vertex AI, strong AI integrations overall. No need to migrate later.
Good until: query patterns get unpredictable and costs spike - use query budgets from day one
MotherDuck (DuckDB) Lightweight alt
$10–30/mo
Cloud-hosted DuckDB - fast for read-heavy analytical SQL on small datasets. Reasonable starting point on paper, but migrating away at 50GB would be significant effort. Given BigQuery's free tier covers early months anyway, the migration risk isn't worth it.
Skip unless: you have a strong DuckDB preference and are confident you won't outgrow it
Snowflake / Fivetran Overkill now
$300–600/mo
Enterprise-grade. Excellent tooling, but the per-credit billing and Fivetran connector costs at this scale are hard to justify. Save this conversation for when volume or compliance requirements demand it.
Revisit when: $2M+ ARR or multi-region data residency requirements

Recommendation: start with BigQuery free tier. It handles 70-store analytics comfortably with no migration risk as data grows. The ETL layer (Airbyte self-hosted) costs $20–40/mo on a small VM - no need for managed Fivetran at this stage.

Section 03

RAG & Knowledge Layer Options

The lightest option that works is the right option. For WJ's doc volume - SOPs, contracts, briefs, past reports - even a full-text search approach may be sufficient before reaching for vector embeddings. The upgrade path is clean; there's no reason to start at the top.

Option Cost Semantic quality Setup effort When to use
Postgres full-text search (FTS) Lightest $0 Keyword match only - no semantic understanding Hours Exact phrase search across SOPs and contracts. Surprisingly effective for structured internal docs where terminology is consistent.
Pinecone Serverless Start here $0–15/mo Excellent Hours Managed, zero-ops, just an API key. Free tier covers WJ's current doc volume. Best fit given BigQuery is the warehouse - no Postgres instance to piggyback on.
pgvector on existing Postgres $0–20/mo Good - true vector similarity search 1–2 days Good option only if a Postgres instance already exists for another reason (e.g., Odoo backend). Don't spin up Postgres just for this.
Chroma (self-hosted) $0 + ~$15/mo VPS Good 1–2 days Purpose-built vector DB. Simpler API than pgvector, good for rapid prototyping. Self-hosted = no vendor dependency.
Weaviate Cloud $0–25/mo Excellent - built-in hybrid search 1 day Adds BM25 + vector hybrid search out of the box. Useful if doc retrieval precision becomes a problem.
OpenAI File Search (Assistants API) $0.10/GB + usage Good Minutes Fastest path to RAG if already using OpenAI. Vendor-managed, no infra. Tradeoff: locked into OpenAI, less control over chunking and retrieval logic.

Embedding cost: running embeddings on WJ's estimated doc corpus (~500 docs × ~3,000 tokens avg = 1.5M tokens) costs $0.03 one-time using OpenAI's text-embedding-3-small at $0.02/1M tokens. Re-embedding on updates is negligible. This is not a meaningful cost line.

Section 04

AI Use Cases - Token Costs

The key cost lever in AI is model selection. Haiku and GPT-4o-mini handle high-volume, structured tasks at a fraction of Sonnet cost. Reserve the more capable models for reasoning-heavy work. At WJ's current scale, total AI token spend should stay well under $10/month for months.

Use case Model recommendation Est. volume / mo Tokens / call Est. monthly cost Notes
CEO Dashboard No AI - BI tool only - - $0 Metabase (self-hosted) queries BigQuery directly. No model involved.
Structured Q&A (text-to-SQL) Claude Haiku Recommended ~100 queries ~2,000 avg ~$0.05/mo Haiku is fast and cheap for schema-aware SQL generation. Use Sonnet only if query complexity regularly fails.
Knowledge Q&A (RAG) Claude Sonnet ~50 queries ~4,000 avg (incl. context chunks) ~$0.75/mo Retrieval adds context tokens. Sonnet justified here - doc reasoning is where quality matters.
Automated weekly reports Claude Haiku ~16 reports ~5,000 avg ~$0.02/mo Scheduled, structured summarization. Haiku is more than capable. Run via n8n or Make.
Inventory alerts / anomaly detection Claude Haiku ~1,000 checks ~500 avg ~$0.13/mo High volume, simple pattern. Haiku built for this. Only escalate to Sonnet when alert logic becomes complex.
Cross-store campaign pattern matching Claude Sonnet ~10 analyses ~6,000 avg ~$0.90/mo The flagship AI use case. Rich multi-store data synthesis justifies the model tier. Still cheap at this volume.
Campaign brief generation Claude Sonnet ~10 briefs ~4,000 output tokens ~$0.60/mo Output-heavy. Sonnet for quality. Consider caching brief templates to reduce generation calls.
Creator onboarding / comms drafts Claude Haiku ~20 drafts ~1,500 avg <$0.01/mo Light templating task. Haiku is fine. Human review before send.

Total AI token cost at current scale: ~$2–3/month. Even at 10× usage growth, this stays under $30/month. The cost pressure in AI comes from context window mismanagement (stuffing too much into prompts) and over-indexing on premium models for routine tasks - both avoidable with intentional design.

Section 05

ETL / Data Pipeline

The connector layer between Shopify, Odoo, and the warehouse. Cost varies enormously depending on whether it's self-hosted or managed.

Option Est. monthly Pros Cons
Airbyte self-hosted Start here $0 software + $10–15/mo VM Purpose-built, 300+ connectors, open-source. Shopify via native connector. Odoo via Postgres connector (read-only DB user) - more reliable than Odoo's community Airbyte connector. VM adds a small fixed cost; Odoo schema is complex so initial table mapping takes time
Airbyte Cloud $100–300/mo Zero-ops, fully managed Per-row pricing can surprise at scale
Fivetran Overkill now $500–2,000/mo Best-in-class connectors, enterprise SLAs Expensive relative to WJ's current data volume; hard to justify pre-scale

Note: n8n and Make/Zapier are automation tools, not ETL - they lack schema management, incremental sync, and reliable warehouse loading. Keep them in the automation layer. For moving data from Odoo into BigQuery, use a purpose-built ETL tool like Airbyte.
